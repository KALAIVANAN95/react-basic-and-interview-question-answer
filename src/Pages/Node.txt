1. What is Node.js?
Node.js is a JavaScript runtime environment that allows JavaScript to run outside the browser. 
It is mainly used to build backend applications, APIs, and server-side logic.

2.What can Node.js do?
✅ Connect with MongoDB
✅ Read and manage files
✅ Create APIs
✅ Authenticate users
✅ Generate JWT tokens
✅ Upload images
✅ Send emails

3.Is Node.js a programming language?
4.No. It is a runtime environment.

5.Is Node.js a framework?
No. Node.js is a runtime environment. Express.js is a framework built on top of Node.js.

6.Why can't React connect directly to MongoDB?
React should not connect directly to MongoDB because database credentials would be exposed to users. 
Instead, React sends requests to the backend (Node.js), and the backend securely communicates with the database.

7.What is Express.js?
Express.js is a lightweight web framework built on top of Node.js
It simplify backend development by providing features like routing(GET,POST,PUT,DELETE),
Middleware(JWT,Authentication,Logging) and Req,Res handling

9.Node.js vs Express.js – What's the Difference?**

10.What is Routing?
Routing maps a request (URL+HTTP method) to the correct controller/function

11.HTTP Methods?
There are 5 important methods

12.What is GET?
Get is used to retrieve data from the server.

13.What is POST?
POST is used to create a new resources on the server

14.What is PUT?
PUT is used to completely update an existing resource.

15.What is PATCH?
PATCH is used to partially update an existing resource.

16.What is DELETE?

17.API
An API (Application Programming Interface) acts as a bridge between the client (React) and the server (Node.js), allowing them to communicate.
React UI → React → Axios → Express Route → Controller → MongoDB → Controller → Express Response → React UI.

18.What is Middleware?
Middleware is a function that executes between the request and the response. It can inspect, modify,
validate, or stop the request before it reaches the controller.

Request => Middleware=>Controller=>Response

19.What can Middleware do?
Middleware can:
✅ Check JWT
✅ Authentication
✅ Authorization
✅ Logging
✅ Validation
✅ Error Handling

20.What is next()?
next() is a function used to pass control from the current middleware to the next middleware
or route handler.
Middleware=>next()=>controller

21.What happens if we don't call next()?
If we don't call next(), the request stops in the current middleware. 
The controller will not execute, and the client may not receive a response.

22.Authentication Middleware
Authentication Middleware verifies the user's identity by checking whether a valid JWT token is present. 
If the token is valid, it calls next() and allows the request to continue. Otherwise, it returns 401 Unauthorized.

23.Authorization Middleware
Authorization Middleware checks whether the authenticated user has permission to access a specific resource or
perform a specific action based on their role (such as Admin or Employee). If the user does not have permission, it returns 403 Forbidden.

24.401 Unauthorized
The user is not authenticated.
401 Unauthorized means the user is not authenticated. This usually happens when the JWT token is missing, invalid, or expired.

25.403 Forbidden
The user is authenticated, but does not have permission.
403 Forbidden means the user is authenticated, but does not have permission to perform the requested action.
